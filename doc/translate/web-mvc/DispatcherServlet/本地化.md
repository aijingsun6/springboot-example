# 本地化(Locale)

Spring架构的大部分组件都支持国际化，Spring Web MVC框架也是如此。DispatcherServlet允许您通过使用客户端的区域设置来自动解析消息。这是通过LocaleResolver对象实现的。

当请求到达时，DispatcherServlet会查找区域设置解析器，如果找到，则会尝试使用它来设置区域设置。通过使用RequestContext.getLocale()方法，您可以随时获取由区域设置解析器解析出的区域设置。

除了自动解析区域设置外，您还可以将拦截器附加到处理器映射（有关处理器映射拦截器的更多信息，请参见“拦截”）上，以便在特定情况下更改区域设置（例如，根据请求中的某个参数）。

区域设置解析器和拦截器定义在org.springframework.web.servlet.i18n包中，并以常规方式在应用程序上下文中进行配置。Spring中包含以下区域设置解析器选项：
- 时区(Time Zone)
- 头信息解析器(Header Resolver)
- Cookie解析器(Cookie Resolver)
- 会话解析器(Session Resolver)
- 区域设置拦截器()


# 1.Time Zone
除了获取客户端的区域设置（locale）之外，了解其时区信息也常常很有用。`LocaleContextResolver` 接口是对 `LocaleResolver` 的扩展，它允许解析器提供更丰富的 `LocaleContext`，其中可能包含时区信息。 
当可用时，可以通过 `RequestContext.getTimeZone()` 方法获取用户的时区。任何注册到 Spring 的 `ConversionService` 中的日期/时间转换器和格式化器对象都会自动使用时区信息。


# 2.Header Resolver

该区域解析器会检查客户端（例如，网页浏览器）发送的请求中的 accept-language 头部字段。通常，该头部字段包含客户端操作系统的区域设置信息。请注意，该解析器不支持时区信息。

# 3. Cookie Resolver
此区域设置解析器会检查客户端上可能存在的 Cookie，以查看是否指定了区域设置（Locale）或时区（TimeZone）。如果指定了这些信息，它将使用这些指定的详细信息。通过使用此区域设置解析器的属性，您可以指定 Cookie 的名称以及最大存活时间。以下示例定义了一个 CookieLocaleResolver：

```java

<bean id="localeResolver" class="org.springframework.web.servlet.i18n.CookieLocaleResolver">

	<property name="cookieName" value="clientlanguage"/>

	<!-- in seconds. If set to -1, the cookie is not persisted (deleted when browser shuts down) -->
	<property name="cookieMaxAge" value="100000"/>

</bean>
```

下表描述了 CookieLocaleResolver 的属性：
|Property|	Default	|Description|
| --- | --- | --- |
|cookieName|class name + LOCALE|The name of the cookie|
|cookieMaxAge|Servlet container default|Cookie在客户端上保留的最长时间。如果指定为-1，则Cookie不会持久保存。它仅在客户端关闭浏览器之前有效。|
|cookiePath|/|限制Cookie的可见范围至网站的某一部分。当指定了cookiePath时，该Cookie仅对该路径及其子路径可见。|

# 4. Session Resolver
SessionLocaleResolver 允许您从会话中检索可能与用户请求关联的 Locale 和 TimeZone。与 CookieLocaleResolver 不同，这种策略将本地选择的区域设置存储在 Servlet 容器的 HttpSession 中。因此，这些设置对每个会话来说是临时的，当每个会话结束时，这些设置也会随之丢失。

请注意，它与外部会话管理机制（如 Spring Session 项目）之间没有直接关系。此 SessionLocaleResolver 会根据当前的 HttpServletRequest 评估并修改相应的 HttpSession 属性。

# 5. Locale Interceptor
您可以通过将 `LocaleChangeInterceptor` 添加到某个 `HandlerMapping` 定义中来启用区域设置更改功能。它会检测请求中的参数，并根据该参数更改区域设置，同时调用调度器应用上下文中 `LocaleResolver` 的 `setLocale` 方法。以下示例表明，对所有包含名为 `siteLanguage` 参数的 *.view 资源的调用都会更改区域设置。例如，对 URL `www.sf.net/home.view?siteLanguage=nl` 的请求会将站点语言更改为荷兰语。以下示例展示了如何拦截区域设置：
```java
<bean id="localeChangeInterceptor"
		class="org.springframework.web.servlet.i18n.LocaleChangeInterceptor">
	<property name="paramName" value="siteLanguage"/>
</bean>

<bean id="localeResolver"
		class="org.springframework.web.servlet.i18n.CookieLocaleResolver"/>

<bean id="urlMapping"
		class="org.springframework.web.servlet.handler.SimpleUrlHandlerMapping">
	<property name="interceptors">
		<list>
			<ref bean="localeChangeInterceptor"/>
		</list>
	</property>
	<property name="mappings">
		<value>/**/*.view=someController</value>
	</property>
</bean>
```
