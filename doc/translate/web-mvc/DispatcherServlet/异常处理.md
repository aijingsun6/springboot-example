# 异常处理(Exceptions)


如果在请求映射过程中发生异常，或者从请求处理器（如@Controller）中抛出异常，DispatcherServlet 会将异常委托给一系列 HandlerExceptionResolver bean 来处理，以提供替代的处理方式，通常表现为一个错误响应。 
以下是可用的 HandlerExceptionResolver 实现列表：

HandlerExceptionResolver 实现表
|HandlerExceptionResolver | Description |
| --- | --- |
| SimpleMappingExceptionResolver | 异常类名与错误视图名称之间的映射。在用于在浏览器应用程序中渲染错误页面时非常有用。|
| DefaultHandlerExceptionResolver | 处理由 Spring MVC 引发的异常，并将其映射为 HTTP 状态码。另请参阅替代方案 ResponseEntityExceptionHandler 和错误响应。 |
| ResponseStatusExceptionResolver | 使用 @ResponseStatus 注解处理异常，并根据注解中的值将其映射到 HTTP 状态码。|
| ExceptionHandlerExceptionResolver | 通过调用@Controller或@ControllerAdvice类中的@ExceptionHandler方法来处理异常。请参阅@ExceptionHandler方法。 |

# 解析器链
您可以通过在 Spring 配置中声明多个 `HandlerExceptionResolver` Bean，并根据需要设置它们的 `order` 属性，来构建一个异常解析器链。`order` 属性值越高，异常解析器被调用的顺序越靠后。

`HandlerExceptionResolver` 的契约规定，它可以返回以下内容：
- 一个指向错误视图的 `ModelAndView`。
- 如果异常在解析器内部已处理，则返回一个空的 `ModelAndView`。
- 如果异常仍未解决，则返回 `null`，以便后续解析器尝试处理。如果最终仍未解决，该异常可以继续向上冒泡到 Servlet 容器。

MVC 配置会自动声明内置的解析器，用于处理默认的 Spring MVC 异常、带有 `@ResponseStatus` 注解的异常，以及支持 `@ExceptionHandler` 方法。您可以自定义该列表或替换它。

# 容器错误页面
如果某个异常未被任何 HandlerExceptionResolver 处理，从而继续传播，或者如果响应状态被设置为错误状态（即 4xx、5xx），Servlet 容器可以渲染一个默认的 HTML 错误页面。要自定义容器的默认错误页面，可以在 web.xml 中声明一个错误页面映射。以下示例展示了如何实现这一点：

```java

<error-page>
	<location>/error</location>
</error-page>
```

根据前面的示例，当异常冒泡或响应具有错误状态时，Servlet容器会在容器内部对配置的URL（例如/error）进行一次ERROR调度。随后，DispatcherServlet会对此进行处理，可能将其映射到一个@Controller上，该控制器可以设计为返回一个带有模型的错误视图名称，或者渲染一个JSON响应，如下例所示：

```java
@RestController
public class ErrorController {

	@RequestMapping(path = "/error")
	public Map<String, Object> handle(HttpServletRequest request) {
		Map<String, Object> map = new HashMap<>();
		map.put("status", request.getAttribute("jakarta.servlet.error.status_code"));
		map.put("reason", request.getAttribute("jakarta.servlet.error.message"));
		return map;
	}
}


```
Servlet API 未提供在 Java 中创建错误页面映射的方法。不过，您可以同时使用 WebApplicationInitializer 和一个精简的 web.xml。
