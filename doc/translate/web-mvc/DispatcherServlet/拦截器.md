# Interception 拦截器

所有 `HandlerMapping` 的实现都支持处理器拦截，这在您希望在请求之间应用某些功能时非常有用。`HandlerInterceptor` 可以实现以下方法：

`preHandle(..)` - 在实际处理器运行之前调用的回调方法，返回一个布尔值。如果该方法返回 `true`，则继续执行；如果返回 `false`，则跳过后续的执行链，不会调用处理器。

`postHandle(..)` - 在处理器运行之后调用的回调方法。

`afterCompletion(..)` - 在整个请求完成之后调用的回调方法。


对于带有 `@ResponseBody` 和 `ResponseEntity` 注解的控制器方法，响应会在 `HandlerAdapter` 中写入并提交，此时 `postHandle` 方法尚未被调用。这意味着此时再更改响应（例如添加额外的头信息）已经太晚了。你可以实现 `ResponseBodyAdvice` 接口，并将其声明为 `@ControllerAdvice` 组件，或者直接将其配置在 `RequestMappingHandlerAdapter` 上。

有关如何配置拦截器的示例，请参阅 MVC 配置部分中的“拦截器”章节。你也可以通过在各个 `HandlerMapping` 实现中使用 setter 方法直接注册拦截器。


拦截器并不完全适合作为安全层，因为它们可能与注解控制器路径匹配存在不匹配的情况。通常，我们建议使用 Spring Security，或者采用类似的方法与 Servlet 过滤器链集成，并尽早应用。
