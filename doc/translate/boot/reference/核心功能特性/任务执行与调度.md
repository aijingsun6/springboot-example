# 任务执行与调度(Task Execution and Scheduling)

在上下文中不存在 Executor bean 的情况下，Spring Boot 会自动配置一个 AsyncTaskExecutor。当启用了虚拟线程（使用 Java 21+ 并将 `spring.threads.virtual.enabled` 设置为 true）时，它将是一个使用虚拟线程的 SimpleAsyncTaskExecutor。否则，它将是一个具有合理默认值的 ThreadPoolTaskExecutor。

除非定义了自定义的 Executor bean，否则自动配置的 AsyncTaskExecutor 将用于以下集成：

- 使用 `@EnableAsync` 执行异步任务，除非定义了类型为 AsyncConfigurer 的 bean。
- 在 Spring for GraphQL 中，对控制器方法返回的 Callable 值进行异步处理。
- Spring MVC 中的异步请求处理。
- Spring WebFlux 中对阻塞执行的支持。
- 在 Spring WebSocket 中用于入站和出站消息通道。
- 基于 JPA 仓库的引导模式的 JPA 引导执行器。
- 用于 ApplicationContext 中 bean 后台初始化的引导执行器。

虽然这种方法在大多数场景下都能正常工作，但 Spring Boot 允许你覆盖自动配置的 AsyncTaskExecutor。默认情况下，当注册了自定义的 Executor bean 时，自动配置的 AsyncTaskExecutor 会退居二线，而自定义的 Executor 将用于常规任务执行（通过 `@EnableAsync`）。

然而，Spring MVC、Spring WebFlux 和 Spring GraphQL 都需要一个名为 `applicationTaskExecutor` 的 bean。对于 Spring MVC 和 Spring WebFlux，该 bean 必须是 AsyncTaskExecutor 类型，而 Spring GraphQL 则不强制要求该类型。

如果存在一个该类型的单例 bean 或者定义了名为 `applicationTaskExecutor` 的 bean，Spring WebSocket 和 JPA 将使用 AsyncTaskExecutor。

最后，ApplicationContext 的引导执行器会使用名为 `applicationTaskExecutor` 的 bean，除非定义了名为 `bootstrapExecutor` 的 bean。

以下代码片段展示了如何注册一个自定义的 AsyncTaskExecutor，以供 Spring MVC、Spring WebFlux、Spring GraphQL、Spring WebSocket、JPA 以及 bean 的后台初始化使用。

```bash
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.core.task.SimpleAsyncTaskExecutor;

@Configuration(proxyBeanMethods = false)
public class MyTaskExecutorConfiguration {

	@Bean("applicationTaskExecutor")
	SimpleAsyncTaskExecutor applicationTaskExecutor() {
		return new SimpleAsyncTaskExecutor("app-");
	}

}
```

如果应用程序上下文中没有 @Primary bean 或名为 taskExecutor 的 Executor 或 AsyncConfigurer 类型的 bean，则 applicationTaskExecutor bean 也将用于常规任务执行。

如果既没有定义自动配置的 AsyncTaskExecutor，也没有定义 applicationTaskExecutor bean，则应用程序将默认使用名为 taskExecutor 的 bean 进行常规任务执行（@EnableAsync），遵循 Spring Framework 的行为。但是，该 bean 不会用于 Spring MVC、Spring WebFlux 或 Spring GraphQL。不过，如果该 bean 的类型为 AsyncTaskExecutor，则它可能用于 Spring WebSocket 或 JPA。

如果您的应用程序需要为不同集成使用多个 Executor bean，例如一个用于通过 @EnableAsync 进行常规任务执行，另一个用于 Spring MVC、Spring WebFlux、Spring WebSocket 和 JPA，则可以按如下方式配置它们。

```bash

import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.core.task.SimpleAsyncTaskExecutor;
import org.springframework.scheduling.concurrent.ThreadPoolTaskExecutor;

@Configuration(proxyBeanMethods = false)
public class MyTaskExecutorConfiguration {

	@Bean("applicationTaskExecutor")
	SimpleAsyncTaskExecutor applicationTaskExecutor() {
		return new SimpleAsyncTaskExecutor("app-");
	}

	@Bean("taskExecutor")
	ThreadPoolTaskExecutor taskExecutor() {
		ThreadPoolTaskExecutor threadPoolTaskExecutor = new ThreadPoolTaskExecutor();
		threadPoolTaskExecutor.setThreadNamePrefix("async-");
		return threadPoolTaskExecutor;
	}

}
```

自动配置的ThreadPoolTaskExecutorBuilder或SimpleAsyncTaskExecutorBuilder使您能够轻松创建AsyncTaskExecutor类型的实例，这些实例可以复制自动配置的默认行为。

```bash
import org.springframework.boot.task.SimpleAsyncTaskExecutorBuilder;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.core.task.SimpleAsyncTaskExecutor;

@Configuration(proxyBeanMethods = false)
public class MyTaskExecutorConfiguration {

	@Bean
	SimpleAsyncTaskExecutor taskExecutor(SimpleAsyncTaskExecutorBuilder builder) {
		return builder.build();
	}

}
```
如果无法使用名为 taskExecutor 的 bean，可以将 bean 标记为 @Primary，或定义一个 AsyncConfigurer bean 来指定负责处理常规任务执行的 Executor（通过 @EnableAsync）。以下示例展示了如何实现这一点。

```bash

import java.util.concurrent.Executor;
import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;

import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.scheduling.annotation.AsyncConfigurer;

@Configuration(proxyBeanMethods = false)
public class MyTaskExecutorConfiguration {

	@Bean
	AsyncConfigurer asyncConfigurer(ExecutorService executorService) {
		return new AsyncConfigurer() {

			@Override
			public Executor getAsyncExecutor() {
				return executorService;
			}

		};
	}

	@Bean
	ExecutorService executorService() {
		return Executors.newCachedThreadPool();
	}

}
```

要在保留自动配置的 AsyncTaskExecutor 的同时注册自定义 Executor，可以创建一个自定义 Executor Bean，并在其 @Bean 注解中设置 defaultCandidate=false 属性，如下例所示：


```bash

import java.util.concurrent.Executors;
import java.util.concurrent.ScheduledExecutorService;

import org.springframework.beans.factory.annotation.Qualifier;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration(proxyBeanMethods = false)
public class MyTaskExecutorConfiguration {

	@Bean(defaultCandidate = false)
	@Qualifier("scheduledExecutorService")
	ScheduledExecutorService scheduledExecutorService() {
		return Executors.newSingleThreadScheduledExecutor();
	}

}
```


在这种情况下，您可以将自定义的 Executor 自动注入到其他组件中，同时保留自动配置的 AsyncTaskExecutor。但请记住，在使用 @Autowired 的同时，还需要使用 @Qualifier 注解。 
如果无法做到这一点，您仍然可以要求 Spring Boot 自动配置一个 AsyncTaskExecutor，方法如下：


```bash

spring.task.execution.mode=force
```



自动配置的 AsyncTaskExecutor 将自动用于所有集成，即使注册了自定义的 Executor bean（包括标记为 @Primary 的 bean）也不例外。这些集成包括：

1. 异步任务执行（@EnableAsync），除非存在 AsyncConfigurer bean。
2. Spring for GraphQL 对控制器方法返回的 Callable 值的异步处理。
3. Spring MVC 的异步请求处理。
4. Spring WebFlux 的阻塞执行支持。
5. 用于 Spring WebSocket 中的入站和出站消息通道。
6. 基于 JPA 仓库的引导模式，为 JPA 提供的引导执行器。
7. 用于 ApplicationContext 中 bean 的后台初始化的引导执行器，除非定义了名为 bootstrapExecutor 的 bean。

根据您的目标配置，您可以设置 spring.task.execution.mode 来强制自动配置 applicationTaskExecutor，将您的 Executor 转换为 AsyncTaskExecutor，或者同时定义一个 AsyncTaskExecutor 和一个包装您自定义 Executor 的 AsyncConfigurer。

当启用强制模式时，即使存在 @Primary bean 或名为 taskExecutor 的 Executor 类型 bean，applicationTaskExecutor 也将被配置用于常规任务执行（@EnableAsync）。覆盖常规任务 Executor 的唯一方法是注册一个 AsyncConfigurer bean。

当 ThreadPoolTaskExecutor 被自动配置时，线程池使用 8 个核心线程，可根据负载进行扩展和收缩。这些默认设置可以通过 spring.task.execution 命名空间进行微调，如下例所示：

```bash

spring.task.execution.pool.max-size=16
spring.task.execution.pool.queue-capacity=100
spring.task.execution.pool.keep-alive=10s
```

这会将线程池更改为使用有界队列，以便在队列满（100个任务）时，线程池会扩展到最多16个线程。线程池的收缩更为激进，因为当线程空闲10秒（而不是默认的60秒）时，它们会被回收。

如果调度器需要与计划任务执行相关联（例如使用 `@EnableScheduling`），也可以自动配置调度器。

如果启用了虚拟线程（使用 Java 21+ 并将 `spring.threads.virtual.enabled` 设置为 true），则调度器将是一个使用虚拟线程的 `SimpleAsyncTaskScheduler`。该 `SimpleAsyncTaskScheduler` 将忽略任何与线程池相关的属性。

如果未启用虚拟线程，调度器将是一个具有合理默认值的 `ThreadPoolTaskScheduler`。`ThreadPoolTaskScheduler` 默认使用一个线程，并且可以通过 `spring.task.scheduling` 命名空间对其设置进行微调，如下例所示：

```bash
spring.task.scheduling.thread-name-prefix=scheduling-
spring.task.scheduling.pool.size=2
```


1. 如果需要创建自定义执行器或调度器，上下文中会提供 ThreadPoolTaskExecutorBuilder bean、SimpleAsyncTaskExecutorBuilder bean、ThreadPoolTaskSchedulerBuilder bean 和 SimpleAsyncTaskSchedulerBuilder。

1. SimpleAsyncTaskExecutorBuilder 和 SimpleAsyncTaskSchedulerBuilder bean 会自动配置为使用虚拟线程（如果已启用，即使用 Java 21+ 并设置 spring.threads.virtual.enabled 为 true）。
