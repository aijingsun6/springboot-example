# 开发工具(Developer Tools)

Spring Boot 包含一组额外的工具，可以使应用程序开发体验更加愉悦。spring-boot-devtools 模块可以包含在任何项目中，以提供额外的开发时功能。要包含 devtools 支持，请将模块依赖项添加到构建中，如下所示，分别是 Maven 和 Gradle 的示例：


maven
```xml

<dependencies>
	<dependency>
		<groupId>org.springframework.boot</groupId>
		<artifactId>spring-boot-devtools</artifactId>
		<optional>true</optional>
	</dependency>
</dependencies>
```
gradle 
```groovy

dependencies {
	developmentOnly("org.springframework.boot:spring-boot-devtools")
}
```

开发工具可能会导致类加载问题，特别是在多模块项目中。《诊断类加载问题》一文解释了如何诊断和解决这些问题。

在运行完全打包的应用程序时，开发者工具会自动禁用。如果您的应用程序是通过 `java -jar` 启动的，或者通过特殊的类加载器启动的，则会被视为“生产环境应用程序”。您可以通过使用 `spring.devtools.restart.enabled` 系统属性来控制此行为。要启用开发者工具（无论使用何种类加载器启动应用程序），请设置 `-Dspring.devtools.restart.enabled=true` 系统属性。在生产环境中，由于运行开发者工具存在安全风险，因此不应执行此操作。要禁用开发者工具，请排除该依赖项，或设置 `-Dspring.devtools.restart.enabled=false` 系统属性。


在 Maven 中将依赖标记为 optional，或在 Gradle 中使用 developmentOnly 配置（如上所示），可以防止 devtools 被传递性地应用到使用你项目的其他模块。

重新打包的归档文件默认不包含 devtools。如果您想使用某个远程 devtools 功能，需要将其包含在内。在使用 Maven 插件时，通过将 includeOptional 属性设置为 true 来选择性地引入可选依赖项。同时，您还需要将 excludeDevtools 属性设置为 false。在使用 Gradle 插件时，需配置任务的 classpath 以包含 developmentOnly 配置。


诊断类加载问题
如“重启与重新加载”部分所述，重启功能是通过使用两个类加载器来实现的。对于大多数应用程序来说，这种方法效果良好。然而，它有时也会导致类加载问题，尤其是在多模块项目中。

要诊断类加载问题是否确实由 devtools 及其两个类加载器引起，可以尝试禁用重启功能。如果这样做解决了问题，可以自定义重启类加载器，使其包含整个项目。

属性默认值
Spring Boot 支持的多个库使用缓存来提高性能。例如，模板引擎会缓存编译后的模板，以避免重复解析模板文件。此外，Spring MVC 在提供静态资源时，可以向响应中添加 HTTP 缓存头。
虽然缓存对生产环境非常有益，但在开发过程中可能会适得其反，导致你无法看到应用程序中刚刚所做的更改。因此，spring-boot-devtools 默认会禁用缓存选项。
缓存选项通常通过 application.properties 文件中的设置进行配置。例如，Thymeleaf 提供了 spring.thymeleaf.cache 属性。
同样，跟踪概率（tracing probability）也是如此，其默认设置为 100% 可能无法记录所有用于测试的跟踪信息。
与其手动设置这些属性，spring-boot-devtools 模块会自动应用合理的开发时配置。

由于在开发 Spring MVC 和 Spring WebFlux 应用程序时需要更多关于 Web 请求的信息，开发者工具建议您为 Web 日志组启用 DEBUG 日志记录。这将为您提供有关传入请求、处理该请求的处理器、响应结果以及其他详细信息。如果您希望记录所有请求的详细信息（包括可能包含敏感信息的内容），可以启用 `spring.mvc.log-request-details` 或 `spring.http.codecs.log-request-details` 配置属性。


# 自动重启(Automatic Restart)


使用 spring-boot-devtools 的应用程序会在类路径上的文件发生变化时自动重启。在 IDE 中工作时，这可能是一个非常有用的特性，因为它为代码更改提供了非常快速的反馈循环。默认情况下，类路径上指向目录的任何条目都会被监控以检测更改。请注意，某些资源（例如静态资源和视图模板）不需要重启应用程序。

触发重启

由于 DevTools 会监控类路径资源，因此触发重启的唯一方式是更新类路径。无论您使用的是 IDE 还是构建工具插件，都必须重新编译修改过的文件才能触发重启。您如何导致类路径更新取决于所使用的工具：

在 Eclipse 中，保存修改过的文件会导致类路径更新并触发重启。

在 IntelliJ IDEA 中，构建项目（Build -> Build Project）具有相同的效果。

如果使用构建工具插件，运行 Maven 的 mvn compile 或 Gradle 的 gradle build 都会触发重启。

如果您使用 Maven 或 Gradle 的构建工具插件进行重启，必须保持 fork 设置为启用状态。如果禁用 fork，devtools 使用的隔离应用程序类加载器将不会被创建，重启功能将无法正常工作。

如果您使用 JRebel，自动重启功能将被禁用，以支持动态类重载。其他 devtools 功能（例如属性覆盖）仍然可以使用。

DevTools 依赖于应用程序上下文的关闭钩子（shutdown hook）来在重启时关闭它。如果您禁用了关闭钩子（SpringApplication.setRegisterShutdownHook(false)），它将无法正常工作。

DevTools 需要自定义 ApplicationContext 使用的 ResourceLoader。如果您的应用程序已经提供了一个 ResourceLoader，它将被包装起来。ApplicationContext 的 getResource 方法不支持直接覆盖。

在使用 AspectJ 织入时，不支持自动重启。


重启与重载
Spring Boot 提供的重启技术通过使用两个类加载器来实现。不经常更改的类（例如来自第三方 JAR 的类）会被加载到基础类加载器中。你正在积极开发的类则会被加载到重启类加载器中。当应用程序重启时，重启类加载器会被丢弃，并创建一个新的类加载器。这种方法意味着应用程序的重启通常比“冷启动”要快得多，因为基础类加载器已经存在并且已经加载了所需的类。

如果你发现重启对于你的应用程序来说还不够快，或者你遇到了类加载问题，你可以考虑使用诸如 ZeroTurnaround 提供的 JRebel 等重载技术。这些技术通过在类加载时对其进行重写，使其更适合重载。
