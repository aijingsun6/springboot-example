# 数据访问
Spring Boot包含了许多用于处理数据源的入门程序。本节回答了与执行此操作相关的问题。

# 配置自定义数据源
要配置自己的 DataSource，定义一个 @Bean 在您的配置中的类型。Spring Boot重用你的 DataSource 任何需要的地方，包括数据库初始化。如果您需要将某些设置外部化，您可以绑定您的 DataSource 对环境的影响(请参见 第三方配置).

以下示例说明如何在Bean中定义数据源：
```java

import org.springframework.boot.context.properties.ConfigurationProperties;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration(proxyBeanMethods = false)
public class MyDataSourceConfiguration {

	@Bean
	@ConfigurationProperties("app.datasource")
	public SomeDataSource dataSource() {
		return new SomeDataSource();
	}

}
```

以下示例说明如何通过设置数据源的属性来定义数据源：

```bash

app:
  datasource:
    url: "jdbc:h2:mem:mydb"
    username: "sa"
    pool-size: 30
```

假设 SomeDataSource 具有URL、用户名和池大小的常规JavaBean属性，这些设置在 DataSource 可供其他组件使用

Spring Boot还提供了一个实用工具构建器类，名为 DataSourceBuilder，可用于创建标准数据源之一（如果它在类路径上）。构建器可以根据类路径上的可用内容来检测使用哪一个。它还会根据JDBC URL自动检测驱动程序。

下面的示例说明如何使用 DataSourceBuilder：

```java

import javax.sql.DataSource;

import org.springframework.boot.context.properties.ConfigurationProperties;
import org.springframework.boot.jdbc.DataSourceBuilder;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration(proxyBeanMethods = false)
public class MyDataSourceConfiguration {

	@Bean
	@ConfigurationProperties("app.datasource")
	public DataSource dataSource() {
		return DataSourceBuilder.create().build();
	}

}
```

用它来运行一个应用 DataSource，只需要连接信息即可。还可以提供特定于池的设置。有关更多详细信息，请检查将在运行时使用的实现。

以下示例显示如何通过设置属性来定义JDBC数据源：

```bash

app:
  datasource:
    url: "jdbc:mysql://localhost/test"
    username: "dbuser"
    password: "dbpass"
    pool-size: 30
```

为了解决这个问题，利用 DataSourceProperties 它将处理 url 到 jdbc-url 为您翻译。您可以初始化一个 DataSourceBuilder 从任何 DataSourceProperties 对象使用其 initializeDataSourceBuilder() 方法。您可以注入 DataSourceProperties 但是，Spring Boot会自动创建，这将您的配置拆分到 spring.datasource.* 和 app.datasource.*.为了避免这种情况，请定义一个自定义的 DataSourceProperties 使用自定义配置属性前缀，如以下示例所示：
```bash

import com.zaxxer.hikari.HikariDataSource;

import org.springframework.boot.context.properties.ConfigurationProperties;
import org.springframework.boot.jdbc.autoconfigure.DataSourceProperties;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.context.annotation.Primary;

@Configuration(proxyBeanMethods = false)
public class MyDataSourceConfiguration {

	@Bean
	@Primary
	@ConfigurationProperties("app.datasource")
	public DataSourceProperties dataSourceProperties() {
		return new DataSourceProperties();
	}

	@Bean
	@ConfigurationProperties("app.datasource.configuration")
	public HikariDataSource dataSource(DataSourceProperties properties) {
		return properties.initializeDataSourceBuilder().type(HikariDataSource.class).build();
	}

}
```


这个设置相当于Spring Boot默认为你做的事情，只是池的类型是在代码中指定的，它的设置暴露为 app.datasource.configuration.* 属性 DataSourceProperties 照顾到 url 到 jdbc-url 翻译，所以可以按如下方式配置

```bash

app:
  datasource:
    url: "jdbc:mysql://localhost/test"
    username: "dbuser"
    password: "dbpass"
    configuration:
      maximum-pool-size: 30
```

请注意，由于自定义配置在代码中指定应使用Hikari。 app.datasource.type 就不会有任何影响

如中所述 支持的连接池， DataSourceBuilder 支持多个不同的连接池。要使用Hikari以外的池，请将其添加到类路径中，请使用 type(Class) 方法来指定要使用的池类，并更新 @Bean 方法的返回类型以匹配。这还将为您提供您选择的特定连接池的配置属性元数据。

Spring Boot会将Hikari特定的设置暴露给 spring.datasource.hikari.本例使用了更通用的 configuration 以子命名空间为例，不支持多数据源实现。
请参见 配置数据源 和 DataSourceAutoConfiguration 类了解更多详细信息

# 配置两个数据源
要定义附加的 DataSource，可以使用与上一节类似的方法。一个关键的区别是 DataSource @Bean 必须声明为 defaultCandidate=false。这可以防止自动配置的 DataSource 从退避三舍

在 Spring框架参考文档 本特性的详细描述如所示。
为了允许额外的 DataSource 要在需要的地方注入，也要用注释它 @Qualifier 如下例所示：

```java

import com.zaxxer.hikari.HikariDataSource;

import org.springframework.beans.factory.annotation.Qualifier;
import org.springframework.boot.context.properties.ConfigurationProperties;
import org.springframework.boot.jdbc.DataSourceBuilder;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration(proxyBeanMethods = false)
public class MyAdditionalDataSourceConfiguration {

	@Qualifier("second")
	@Bean(defaultCandidate = false)
	@ConfigurationProperties("app.datasource")
	public HikariDataSource secondDataSource() {
		return DataSourceBuilder.create().type(HikariDataSource.class).build();
	}

}
```

要消耗额外的 DataSource，用相同的注解注入点 @Qualifier.

自动配置和附加数据源可按以下方式配置：

```bash

spring:
  datasource:
    url: "jdbc:mysql://localhost/first"
    username: "dbuser"
    password: "dbpass"
    configuration:
      maximum-pool-size: 30
app:
  datasource:
    url: "jdbc:mysql://localhost/second"
    username: "dbuser"
    password: "dbpass"
    max-total: 30
```

更高级的、特定于实现的、配置自动配置的 DataSource 可通过 spring.datasource.configuration.* 属性。您可以将相同的概念应用于其他 DataSource 以及，如以下示例所示：

```java

import com.zaxxer.hikari.HikariDataSource;

import org.springframework.beans.factory.annotation.Qualifier;
import org.springframework.boot.context.properties.ConfigurationProperties;
import org.springframework.boot.jdbc.autoconfigure.DataSourceProperties;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration(proxyBeanMethods = false)
public class MyCompleteAdditionalDataSourceConfiguration {

	@Qualifier("second")
	@Bean(defaultCandidate = false)
	@ConfigurationProperties("app.datasource")
	public DataSourceProperties secondDataSourceProperties() {
		return new DataSourceProperties();
	}

	@Qualifier("second")
	@Bean(defaultCandidate = false)
	@ConfigurationProperties("app.datasource.configuration")
	public HikariDataSource secondDataSource(@Qualifier("second") DataSourceProperties dataSourceProperties) {
		return dataSourceProperties.initializeDataSourceBuilder().type(HikariDataSource.class).build();
	}

}
```

上面的示例使用与Spring Boot在自动配置中使用相同的逻辑配置额外的数据源。需要注意的是 app.datasource.configuration.* 属性提供基于所选实现的高级设置。

如与 配置单个自定义 DataSource的类型，其中一个或两个 DataSource bean可以使用 type(Class) 上的方法 DataSourceBuilder.参见 支持的连接池 了解支持的类型的详细信息。


# 使用Spring数据存储库

Spring Data可以创建的实现 Repository 各种规格的接口。Spring Boot为你处理所有这些，只要那些 Repository 实现包括在 自动配置包，通常是主应用程序类的包（或子包），用 @SpringBootApplication 或 @EnableAutoConfiguration.

对于许多应用程序，你所需要的只是将正确的Spring Data依赖项放在你的类路径上。有一个 spring-boot-starter-data-jpa 对于JPA， spring-boot-starter-data-mongodb 用于Mongodb，以及其他各种支持技术的入门者。要开始，请创建一些存储库接口来处理您的 @Entity 对象

Spring Boot确定你的位置 Repository 的实现，通过扫描 自动配置包。要获得更多的控制，请使用 @Enable…Repositories Spring Data中的注解。

有关Spring Data的更多信息，请参见 Spring Data项目页面.

## @实体定义与Spring配置分离(@实体定义与Spring配置分离)

Spring Boot确定你的位置 @Entity 定义，通过扫描 自动配置包。要获得更多的控制，请使用 @EntityScan 注解，如以下示例所示：

```bash
import org.springframework.boot.autoconfigure.EnableAutoConfiguration;
import org.springframework.boot.persistence.autoconfigure.EntityScan;
import org.springframework.context.annotation.Configuration;

@Configuration(proxyBeanMethods = false)
@EnableAutoConfiguration
@EntityScan(basePackageClasses = City.class)
public class MyApplication {

	// ...

}
```

## 筛选扫描@实体定义
可以过滤 @Entity 定义使用 ManagedClassNameFilter 当只考虑可用实体的子集时，这在测试中很有用。在下面的示例中，只有来自 com.example.app.customer 套餐包括：

```bash

import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.orm.jpa.persistenceunit.ManagedClassNameFilter;

@Configuration(proxyBeanMethods = false)
public class MyEntityScanConfiguration {

	@Bean
	public ManagedClassNameFilter entityScanFilter() {
		return (className) -> className.startsWith("com.example.app.customer.");
	}

}


```
