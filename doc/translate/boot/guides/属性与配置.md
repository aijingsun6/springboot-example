# 属性与配置 (Properties and Configuration)


本节包含有关设置和读取属性及配置设置以及它们与 Spring Boot 应用程序交互的主题。

# 1. 在构建时自动扩展属性
与其硬编码一些在项目构建配置中也指定的属性，不如通过使用现有的构建配置来自动扩展它们。这在 Maven 和 Gradle 中都是可行的。

# 2.使用 Maven 自动扩展属性
您可以通过使用资源过滤在 Maven 项目中自动扩展属性。如果您使用了 spring-boot-starter-parent，那么您可以使用 @..@ 占位符来引用 Maven 的“项目属性”，如下例所示：

```bash

app:
  encoding: "@project.build.sourceEncoding@"
  java:
    version: "@java.version@"
```
只有生产配置会以这种方式进行过滤（换句话说，src/test/resources 不会应用过滤）。
如果你启用了 addResources 标志，spring-boot:run 目标可以直接将 src/main/resources 添加到类路径中（用于热重载）。这样做会绕过资源过滤和此功能。相反，你可以使用 exec:java 目标或自定义插件的配置。更多详情请参见插件使用页面。
如果你不使用 starter 父项目，你需要在 pom.xml 的 <build/> 元素中包含以下元素：

```bash

<resources>
	<resource>
		<directory>src/main/resources</directory>
		<filtering>true</filtering>
	</resource>
</resources>
```
你还需要在<plugins/>标签内包含以下元素：

```bash

<plugin>
	<groupId>org.apache.maven.plugins</groupId>
	<artifactId>maven-resources-plugin</artifactId>
	<version>2.7</version>
	<configuration>
		<delimiters>
			<delimiter>@</delimiter>
		</delimiters>
		<useDefaultDelimiters>false</useDefaultDelimiters>
	</configuration>
</plugin>
```

如果你在配置中使用标准的Spring占位符（例如${placeholder}），那么useDefaultDelimiters属性就很重要。如果该属性未设置为false，这些占位符可能会被构建过程展开。


# 3. 使用Gradle实现自动属性扩展

您可以通过配置 Java 插件的 processResources 任务来自动扩展 Gradle 项目中的属性，如下例所示：

```bash

tasks.named('processResources') {
	expand(project.properties)
}
```

然后，您可以通过占位符来引用 Gradle 项目的属性，如下例所示：

```bash

app:
  name: "${name}"
  description: "${description}"
```

Gradle 的 expand 方法使用了 Groovy 的 SimpleTemplateEngine，它会转换 ${..} 标记。${..} 这种风格与 Spring 自身的属性占位符机制存在冲突。若要同时使用 Spring 属性占位符和自动扩展功能，需按以下方式转义 Spring 属性占位符：\${..}。



# 4. 将 SpringApplication 的配置外部化
SpringApplication 具有 bean 属性设置器，因此您可以在创建应用程序时使用其 Java API 来修改其行为。或者，您也可以通过在 spring.main.* 中设置属性来将配置外部化。例如，在 application.properties 中，您可能会有以下设置：

```bash


spring:
  main:
    web-application-type: "none"
    banner-mode: "off"
```

那么，Spring Boot 的启动横幅将不会在启动时打印，并且应用程序也不会启动嵌入式 Web 服务器。 
外部配置中定义的属性会覆盖并替换通过 Java API 指定的值，但主要来源（primary sources）是一个显著的例外。主要来源是指提供给 SpringApplication 构造函数的属性：

```bash
import org.springframework.boot.Banner;
import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;

@SpringBootApplication
public class MyApplication {

	public static void main(String[] args) {
		SpringApplication application = new SpringApplication(MyApplication.class);
		application.setBannerMode(Banner.Mode.OFF);
		application.run(args);
	}

}
```

```bash
import org.springframework.boot.Banner;
import org.springframework.boot.builder.SpringApplicationBuilder;

public class MyApplication {

	public static void main(String[] args) {
		new SpringApplicationBuilder()
			.bannerMode(Banner.Mode.OFF)
			.sources(MyApplication.class)
			.run(args);
	}

}
```

```bash

spring:
  main:
    sources: "com.example.MyDatabaseConfig,com.example.MyJmsConfig"
    banner-mode: "console"
```

实际应用将显示横幅（根据配置覆盖），并使用三个来源为 ApplicationContext 提供数据。这些应用来源包括：
- MyApplication（来自代码）
- MyDatabaseConfig（来自外部配置）
- MyJmsConfig（来自外部配置）

# 更改应用程序外部属性的位置

默认情况下，来自不同来源的属性会按照定义的顺序添加到 Spring 环境中（具体顺序请参见“Spring Boot 特性”部分的“外部化配置”）。

您还可以通过提供以下系统属性（或环境变量）来改变行为：
spring.config.name（SPRING_CONFIG_NAME）：默认为 application，作为文件名的根名称。
spring.config.location（SPRING_CONFIG_LOCATION）：要加载的文件（例如类路径资源或 URL）。为此文档会设置一个独立的环境属性源，并且该属性源可以被系统属性、环境变量或命令行覆盖。

无论您在环境中设置了什么，Spring Boot 都会如上所述始终加载 application.properties。默认情况下，如果使用 YAML，则扩展名为 '.yaml' 和 '.yml' 的文件也会被添加到列表中。

如果您希望获取有关正在加载的文件的详细信息，可以将 org.springframework.boot.context.config 的日志级别设置为 trace。

# 使用“短”命令行参数

有些人喜欢在命令行中使用（例如）`--port=9000` 而不是 `--server.port=9000` 来设置配置属性。你可以通过在 `application.properties` 中使用占位符来启用这种行为，如下例所示

```bash

server:
  port: "${port:8080}"
```

如果您继承了 spring-boot-starter-parent 的 POM，maven-resources-plugin 的默认过滤标记已从 ${*} 更改为 @（即使用 @maven.token@ 而非 ${maven.token}），以避免与 Spring 风格的占位符产生冲突。如果您已直接为 application.properties 启用了 Maven 过滤功能，可能还需要将默认过滤标记更改为其他分隔符。

在此特定场景中，端口绑定适用于 Heroku 或 Cloud Foundry 等 PaaS 环境。在这两个平台上，PORT 环境变量会自动设置，Spring 可以绑定到环境属性的大写同义词。

# 使用YAML作为外部属性

YAML 是 JSON 的超集，因此是一种方便的语法，可用于以分层格式存储外部属性，如下例所示。

```bash

spring:
  application:
    name: "cruncher"
  datasource:
    driver-class-name: "com.mysql.jdbc.Driver"
    url: "jdbc:mysql://localhost/test"
server:
  port: 9000
```

创建一个名为 application.yaml 的文件，并将其放在类路径的根目录下。然后将 snakeyaml 添加到你的依赖项中（Maven 坐标 org.yaml:snakeyaml，如果你使用的是 spring-boot-starter，它已经包含在内）。YAML 文件会被解析为 Java 的 Map<String, Object>（类似于 JSON 对象），Spring Boot 会将该 Map 展平，使其只有一层深度，并且使用点号分隔的键，这与 Java 中的 Properties 文件的用法类似。

前面的 YAML 示例对应于以下 application.properties 文件：

```bash
spring.application.name=cruncher
spring.datasource.driver-class-name=com.mysql.jdbc.Driver
spring.datasource.url=jdbc:mysql://localhost/test
server.port=9000
```

# 设置活动Spring配置文件(Set the Active Spring Profiles)

Spring 环境为此提供了一个 API，但通常你会设置一个系统属性（spring.profiles.active）或操作系统环境变量（SPRING_PROFILES_ACTIVE）。此外，你也可以通过 -D 参数启动应用程序（记得将其放在主类或 jar 归档文件之前），如下所示：

```bash
$ java -jar -Dspring.profiles.active=production demo-0.0.1-SNAPSHOT.jar
```

在 Spring Boot 中，你也可以在 application.properties 文件中设置激活的配置文件，如下例所示：

```bash

spring:
  profiles:
    active: "production"
```

以这种方式设置的值会被系统属性或环境变量设置所覆盖，但不会被 `SpringApplicationBuilder.profiles()` 方法覆盖。因此，可以使用后者的 Java API 来扩展配置文件，而无需更改默认值。 
更多信息请参阅“Spring Boot 特性”部分中的配置文件相关内容。

# 设置默认配置文件名称 (Set the Default Profile Name)

默认配置文件是指在没有激活任何配置文件时启用的配置文件。默认情况下，该配置文件的名称为 default，但可以通过系统属性（spring.profiles.default）或操作系统环境变量（SPRING_PROFILES_DEFAULT）来更改其名称。在 Spring Boot 中，您还可以在 application.properties 文件中设置默认配置文件名称，如下例所示：

```bash
spring:
  profiles:
    default: "dev"
```

# 根据环境更改配置(Change Configuration Depending on the Environment)
Spring Boot 支持多文档 YAML 和 Properties 文件（详见《处理多文档文件》），这些文件可以根据激活的配置文件有条件地启用。 
如果一个文档中包含 `spring.config.activate.on-profile` 键，则该文档中的 `profiles` 值（一个以逗号分隔的配置文件列表或一个配置文件表达式）将被传递给 Spring Environment 的 `acceptsProfiles()` 方法。如果该配置文件表达式匹配，则该文档将被包含在最终的合并结果中（否则不会），如下例所示：

```bash

server:
  port: 9000
---
spring:
  config:
    activate:
      on-profile: "development"
server:
  port: 9001
---
spring:
  config:
    activate:
      on-profile: "production"
server:
  port: 0
```


在前面的示例中，默认端口为9000。但是，如果名为“development”的Spring配置文件处于活动状态，则端口为9001。如果“production”处于活动状态，则端口为0。


# 探索外部属性的内置选项

Spring Boot 在运行时将外部属性（来自 application.properties 或 YAML 文件及其他位置）绑定到应用程序中。由于可以通过类路径中的其他 jar 文件进行扩展，因此无法（从技术上讲也不可能）在单一位置提供所有支持属性的详尽列表。

具有 Actuator 功能的运行应用程序会提供一个 `configprops` 端点，用于显示所有可通过 `@ConfigurationProperties` 注解绑定的属性及其可绑定属性。

附录中包含一个 `application.properties` 示例，其中列出了 Spring Boot 支持的最常见属性。权威的完整列表可以通过搜索源代码中的 `@ConfigurationProperties` 和 `@Value` 注解，以及偶尔使用 `Binder` 来获取。有关属性加载顺序的详细信息，请参阅外部化配置。
