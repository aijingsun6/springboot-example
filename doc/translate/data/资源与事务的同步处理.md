# 资源与事务的同步处理

Synchronizing Resources with Transactions

现在应该已经清楚如何创建不同的事务管理器，以及它们如何与需要同步到事务的相关资源关联（例如，DataSourceTransactionManager 关联到 JDBC 的 DataSource，HibernateTransactionManager 关联到 Hibernate 的 SessionFactory，等等）。本节将描述应用程序代码（直接或间接通过使用 JDBC、Hibernate 或 JPA 等持久化 API）如何确保这些资源被正确创建、重用和清理。本节还将讨论事务同步如何通过相关的事务管理器（可选地）被触发。

# 高级同步方法
首选的方法是使用 Spring 最高级别的基于模板的持久化集成 API，或者使用具有事务感知能力的工厂 Bean 或代理来管理原生资源工厂，并结合原生 ORM API。这些具有事务感知能力的解决方案在内部处理资源的创建与重用、清理、资源的事务同步（可选）以及异常映射。因此，用户的数据访问代码无需处理这些任务，可以专注于纯粹的非样板化持久化逻辑。通常，您可以使用原生 ORM API，或者通过 JdbcTemplate 采用模板化方式进行 JDBC 访问。这些解决方案将在本参考文档的后续章节中详细说明。

# 低级同步方法
DataSourceUtils（用于JDBC）、EntityManagerFactoryUtils（用于JPA）、SessionFactoryUtils（用于Hibernate）等类存在于较低层级。当您希望应用程序代码直接处理原生持久化API的资源类型时，可以使用这些类来确保获取到Spring框架管理下的正确实例，（可选地）同步事务，并将过程中发生的异常映射到一致的API。

例如，在JDBC场景中，您无需采用传统JDBC方式直接调用DataSource的getConnection()方法，而是可以使用Spring的org.springframework.jdbc.datasource.DataSourceUtils类，如下所示：

Connection conn = DataSourceUtils.getConnection(dataSource)；

如果当前事务已存在一个同步（关联）的连接实例，则直接返回该实例。否则，该方法调用会触发新连接的创建，该连接（可选地）与当前事务同步，并可在同一事务中供后续重用。如前所述，任何SQLException都会被包装为Spring框架的CannotGetJdbcConnectionException，这是Spring框架中未检查的DataAccessException类型层次结构的一部分。这种方法能提供比直接从SQLException中获取更丰富的信息，并确保在不同数据库甚至不同持久化技术之间的可移植性。

此方法无需Spring事务管理即可使用（事务同步是可选的），因此无论是否使用Spring进行事务管理，您都可以采用这种方式。

当然，一旦您使用了Spring的JDBC支持、JPA支持或Hibernate支持，通常就不再需要使用DataSourceUtils或其他辅助类了，因为通过Spring的抽象层进行操作比直接使用相关API更令人满意。例如，如果您使用Spring的JdbcTemplate或jdbc.object包来简化JDBC操作，正确的连接获取会在后台自动完成，您无需编写任何特殊代码。

# TransactionAwareDataSourceProxy
在最底层存在 TransactionAwareDataSourceProxy 类。这是一个目标 DataSource 的代理，它包装目标 DataSource 以增加对 Spring 管理的事务的感知能力。在这方面，它类似于 Jakarta EE 服务器提供的支持事务的 JNDI DataSource。

您几乎不需要或不想使用这个类，除非现有代码必须被调用并传入一个标准的 JDBC DataSource 接口实现。在这种情况下，这段代码可能是可用的，但正在参与 Spring 管理的事务。您可以通过使用前面提到的更高级别的抽象来编写您的新代码。
