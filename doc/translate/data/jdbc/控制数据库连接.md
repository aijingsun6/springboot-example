# 控制数据库连接

# DataSource

Spring 通过 DataSource 获取数据库连接。DataSource 是 JDBC 规范的一部分，是一个通用的连接工厂。它使容器或框架能够将连接池和事务管理问题隐藏在应用程序代码之外。作为开发者，你无需了解如何连接到数据库的细节。这是设置数据源的管理员的责任。在开发和测试代码时，你很可能同时扮演这两个角色，但你并不一定需要知道生产环境中的数据源是如何配置的。

当你使用 Spring 的 JDBC 层时，你可以从 JNDI 中获取数据源，也可以使用第三方提供的连接池实现来配置你自己的数据源。传统的选择是 Apache Commons DBCP 和 C3P0，它们提供了 bean 风格的数据源类；而对于现代的 JDBC 连接池，可以考虑使用 HikariCP，它提供了构建器风格的 API。

您应该仅将 DriverManagerDataSource 和 SimpleDriverDataSource 类（包含在 Spring 发行版中）用于测试目的！这些变体不提供连接池功能，并且在多次请求连接时会表现不佳。

以下部分将使用 Spring 的 DriverManagerDataSource 实现。稍后将介绍其他几种 DataSource 变体。

要配置 DriverManagerDataSource：
使用 DriverManagerDataSource 获取连接，其方式与获取 JDBC 连接的方式相同。
指定 JDBC 驱动程序的完全限定类名，以便 DriverManager 可以加载该驱动程序类。
提供一个 URL，该 URL 因 JDBC 驱动程序而异。（请参阅驱动程序的文档以获取正确的值。）
提供用户名和密码以连接到数据库。
以下示例展示了如何配置 DriverManagerDataSource：

以下示例展示了如何配置 DriverManagerDataSource

```java

@Bean
DriverManagerDataSource dataSource() {
	DriverManagerDataSource dataSource = new DriverManagerDataSource();
	dataSource.setDriverClassName("org.hsqldb.jdbcDriver");
	dataSource.setUrl("jdbc:hsqldb:hsql://localhost:");
	dataSource.setUsername("sa");
	dataSource.setPassword("");
	return dataSource;
}
```

```xml

<bean id="dataSource" class="org.springframework.jdbc.datasource.DriverManagerDataSource">
	<property name="driverClassName" value="${jdbc.driverClassName}"/>
	<property name="url" value="${jdbc.url}"/>
	<property name="username" value="${jdbc.username}"/>
	<property name="password" value="${jdbc.password}"/>
</bean>

<context:property-placeholder location="jdbc.properties"/>
```

# DataSourceUtils
DataSourceUtils 类是一个方便且功能强大的辅助类，提供静态方法用于从 JNDI 获取连接，并在必要时关闭连接。它支持与 DataSourceTransactionManager 以及 JtaTransactionManager 和 JpaTransactionManager 配合使用线程绑定的 JDBC 连接。

请注意，JdbcTemplate 隐含使用 DataSourceUtils 获取连接，在每个 JDBC 操作背后都使用它，从而隐式参与正在进行的交易。

# SmartDataSource

SmartDataSource 接口应由能够提供与关系数据库连接的类实现。它扩展了 DataSource 接口，以便使用该接口的类可以查询在给定操作之后是否应该关闭连接。当你知道需要重用连接时，这种用法是高效的。

# AbstractDataSource
AbstractDataSource 是 Spring 中 DataSource 实现的抽象基类。它实现了所有 DataSource 实现所共有的代码。如果您编写自己的 DataSource 实现，应该扩展 AbstractDataSource 类。

# SingleConnectionDataSource
`SingleConnectionDataSource` 类是 `SmartDataSource` 接口的一个实现，它封装了一个在每次使用后不会关闭的单一连接。该类不支持多线程操作。

如果任何客户端代码在假设使用连接池的情况下（例如在使用持久化工具时）调用 `close` 方法，您应将 `suppressClose` 属性设置为 `true`。此设置会返回一个封装了物理连接的关闭抑制代理。请注意，您将无法再将此代理强制转换为原生 Oracle Connection 或类似对象。

`SingleConnectionDataSource` 主要是一个测试类。它通常用于在应用程序服务器之外的环境中，结合一个简单的 JNDI 环境，方便地测试代码。与 `DriverManagerDataSource` 不同，它始终重用同一个连接，从而避免了物理连接的过度创建。

# DriverManagerDataSource

DriverManagerDataSource 类是标准 DataSource 接口的一种实现，它通过 bean 属性配置一个普通的 JDBC 驱动程序，并在每次请求时返回一个新的 Connection。

该实现适用于 Jakarta EE 容器之外的测试和独立环境，既可以在 Spring IoC 容器中作为 DataSource bean 使用，也可以与简单的 JNDI 环境配合使用。假设连接池的 Connection.close() 调用会关闭连接，因此任何感知 DataSource 的持久化代码都应能正常工作。然而，即使在测试环境中，使用 JavaBean 风格的连接池（如 commons-dbcp）也非常简单，因此几乎总是优先使用此类连接池，而不是 DriverManagerDataSource。

# TransactionAwareDataSourceProxy

`TransactionAwareDataSourceProxy` 是一个用于目标 `DataSource` 的代理。该代理包装了目标 `DataSource`，以添加对 Spring 管理事务的感知能力。在这方面，它与 Jakarta EE 服务器提供的具有事务性的 JNDI DataSource 类似。

通常不建议使用此类，除非必须调用现有代码并且需要传递一个标准的 JDBC DataSource 接口实现。在这种情况下，你仍然可以使这段代码可用，同时让这段代码参与 Spring 管理的事务。通常更推荐的做法是使用更高层次的资源管理抽象（如 `JdbcTemplate` 或 `DataSourceUtils`）来编写你自己的新代码。

更多详情请参见 `TransactionAwareDataSourceProxy` 的 JavaDoc。

# DataSourceTransactionManager / JdbcTransactionManager

DataSourceTransactionManager 类是针对单个 JDBC DataSource 的 PlatformTransactionManager 实现。它将来自指定 DataSource 的 JDBC Connection 绑定到当前执行线程，从而可能允许每个 DataSource 拥有一个线程绑定的 Connection。

应用程序代码必须通过 DataSourceUtils.getConnection(DataSource) 获取 JDBC Connection，而不是使用 Java EE 标准的 DataSource.getConnection 方法。它抛出的是未经检查的 org.springframework.dao 异常，而不是已检查的 SQLException。所有框架类（如 JdbcTemplate）都隐式使用此策略。如果不与事务管理器一起使用，该查找策略的行为与 DataSource.getConnection 完全相同，因此可以在任何情况下使用。

DataSourceTransactionManager 类支持保存点（PROPAGATION_NESTED）、自定义隔离级别以及作为适当 JDBC 语句查询超时应用的超时设置。为了支持后者，应用程序代码必须使用 JdbcTemplate，或为每个创建的语句调用 DataSourceUtils.applyTransactionTimeout(..) 方法。

在单资源情况下，可以使用 DataSourceTransactionManager 替代 JtaTransactionManager，因为它不需要容器支持 JTA 事务协调器。只要遵循所需的连接查找模式，在这两个事务管理器之间切换只是配置问题。请注意，JTA 不支持保存点或自定义隔离级别，并且具有不同的超时机制，但在 JDBC 资源以及 JDBC 提交/回滚管理方面，其行为表现类似。

为了实现 JTA 风格的实际资源连接延迟获取，Spring 提供了针对目标连接池的相应 DataSource 代理类：请参阅 LazyConnectionDataSourceProxy。这在可能为空且没有实际语句执行的事务中特别有用（在这种情况下永远不会获取实际资源），也适用于路由 DataSource 的前端，这意味着需要考虑事务同步的只读标志和/或隔离级别（例如 IsolationLevelDataSourceRouter）。

LazyConnectionDataSourceProxy 还为只读事务期间使用的只读连接池提供特殊支持，避免了在从主连接池获取连接时在每个事务开始和结束时切换 JDBC Connection 的只读标志所带来的开销（根据 JDBC 驱动程序的不同，这可能是昂贵的）。

注意:
从5.3版本开始，Spring提供了一个扩展的`JdbcTransactionManager`变体，该变体在提交/回滚时增加了异常转换功能（与`JdbcTemplate`保持一致）。与`DataSourceTransactionManager`只会抛出`TransactionSystemException`（类似于JTA）不同，`JdbcTransactionManager`会将数据库锁定失败等异常转换为相应的`DataAccessException`子类。请注意，应用程序代码需要为此类异常做好准备，而不能仅依赖于`TransactionSystemException`。在需要这种功能的场景中，推荐使用`JdbcTransactionManager`。

在异常行为方面，JdbcTransactionManager 大致等同于 JpaTransactionManager，也等同于 R2dbcTransactionManager，它们彼此之间可以作为直接的替代品。另一方面，DataSourceTransactionManager 则等同于 JtaTransactionManager，并且可以直接作为其替代品。
